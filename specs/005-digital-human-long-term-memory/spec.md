# 数字人长期记忆按需召回

## 背景

当前数字人在每次运行前固定注入最近更新的 50 条长期记忆。该方式不理解当前问题，容易把无关记忆放入上下文，也会使较早但相关的记忆无法被召回。

本功能只改长期记忆的召回侧。`digital_human_memories` 继续作为唯一事实源，现有记忆沉淀、修订、失效、撤销和权限模型均保持不变。

## 目标

- 将长期记忆召回封装成数字人运行时可调用的 Skill/Tool。
- 由 Agent 根据当前问题决定是否调用召回能力。
- 使用当前问题作为检索 query，调用现有知识库检索链路进行向量/混合召回。
- 每个数字人拥有一个系统内部的长期记忆知识库投影，该知识库对用户不可见、不可绑定、不可编辑。
- 数据库中的当前可见记忆与知识库投影保持同步。
- 删除固定最近 50 条长期记忆注入。

## 非目标

- 不修改 `digital_human_memories` 的事实字段和写入流程。
- 不修改记忆抽取、合并、修订、失效和撤销语义。
- 不把内部长期记忆知识库加入 `digital_human_resource_bindings`。
- 不在前端展示内部知识库或提供用户配置入口。
- 不在召回失败或无结果时静默退化为最近 50 条。

## 用户故事

### US1：数字人按问题召回长期记忆（P1）

当用户的问题可能依赖数字人的长期记忆时，Agent 可以调用长期记忆 Skill，以当前问题检索相关记忆；不相关的最近记忆不应被自动注入。

### US2：内部知识库对用户无感（P1）

用户查看数字人配置、绑定知识库和知识库候选列表时，不应看到长期记忆内部知识库，也不能通过公开接口修改或删除它。

### US3：投影与事实源一致（P1）

记忆新增、更新、失效、归档或被 supersede 后，内部知识库最终只包含数据库当前可见视图；同步失败可重试，并且旧版本不能作为正常召回结果返回。

## 功能需求

- FR-001：运行时必须移除固定最近 50 条长期记忆上下文注入。
- FR-002：运行时提供 `retrieve_digital_human_memory` 工具，输入至少包含非空 `query`。
- FR-003：工具只能使用当前数字人、组织、工作区和授权 scope；Agent 不得传入数字人 ID、知识库 ID 或权限过滤条件。
- FR-004：`top_k` 可由 Agent 在后端限制范围内调整；检索模式、阈值、重排、权重和嵌入模型默认使用内部知识库配置。
- FR-005：内部知识库关联只由后端内部配置读取，不返回到数字人资源绑定、知识库候选或普通知识库列表接口。
- FR-006：内部投影文档必须保留事实源记忆 ID、revision、content digest、status、memory class/type/scope 等来源元数据。
- FR-007：只有数据库当前 active 且在授权 scope 内的记忆可以被返回；invalidated、archived、superseded 或过期投影不得正常召回。
- FR-008：无配置、无结果、投影暂不可用和检索错误必须通过明确状态返回，不得隐式回退最近 50 条。
- FR-009：现有知识库检索服务作为底层执行引擎，不新增一套独立的检索算法。

## 验收标准

- 较早但与当前 query 相关的记忆可以被召回，即使它不在最近 50 条内。
- 与当前 query 无关的最近记忆不会自动出现在系统提示词中。
- 内部知识库不会出现在数字人“知识库”绑定区域和候选列表中。
- 不同数字人的投影和召回严格隔离。
- 记忆更新或失效后，旧 revision 不会继续作为有效结果返回。
- 召回结果包含来源摘要和分数，便于 Agent 判断结果是否足够。
