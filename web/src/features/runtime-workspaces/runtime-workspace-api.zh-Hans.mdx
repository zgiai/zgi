## 接入概览

### Base URL

<CodeGroup title="Base URL">

```text
{apibase}
```

</CodeGroup>

### 核心标识

| 名称 | 用途 | 处理要求 |
| --- | --- | --- |
| Runtime Key | 鉴权当前外部接入的所有请求 | 必须保密 |
| App ID | 标识要调用的 App（智能体或数字人），出现在接口路径中 | 可公开 |
| External User ID | 标识业务系统中的最终用户，隔离文件、会话和记忆 | 使用不透明标识，不包含个人信息 |

App ID 由系统生成并保持稳定。App 重新发布或 Runtime Key 轮换不会改变 App ID。

### 通用请求头

<Properties>
  <Property name='Authorization' type='string' propKey='Authorization'>必填。格式为 `Bearer {'<runtime-key>'}`。</Property>
  <Property name='X-ZGI-External-User-ID' type='string' propKey='X-ZGI-External-User-ID'>调用具体 App、文件、会话和记忆接口时必填。使用稳定、不透明、区分大小写的业务用户标识，长度 1–128 个 Unicode 字符。</Property>
  <Property name='Content-Type' type='string' propKey='Content-Type'>JSON 请求固定为 `application/json`。</Property>
  <Property name='Idempotency-Key' type='uuid' propKey='Idempotency-Key'>记忆写操作可选。重复请求使用相同值可避免重复写入。</Property>
  <Property name='If-Match' type='integer' propKey='If-Match'>更新或删除记忆时可传当前 revision，避免并发覆盖。</Property>
</Properties>

Runtime Key 只应保存在业务服务端。浏览器或移动端应通过业务 BFF 调用 ZGI。

管理员可以在控制台「额度与用量」页设置请求频率：整个外部接入每分钟的请求数，以及每个终端用户每分钟的请求数。超过整体限制时返回 `429`，并带上 `X-RateLimit-Limit` 和 `X-RateLimit-Remaining`；超过单个终端用户的限制时返回 `429` `runtime_end_user_rate_limited`，并带上 `X-RateLimit-End-User-Limit` 和 `X-RateLimit-End-User-Remaining`。两者都带 `Retry-After`，客户端应等到窗口重置后再重试。限流按自然分钟计数；不带 `X-ZGI-External-User-ID` 的管理请求不计入单个终端用户的限制；限流服务不可用时请求不受限。

创建 Runtime Key 时可以限定权限范围，创建后不能修改。`runtime` 允许以终端用户身份调用 App、文件和套餐列表；`end_users.read` 允许读取终端用户；`end_users.manage` 允许修改终端用户、发放积分、导出和删除，并包含读取。还可以只允许调用指定的 App：其他 App 不会出现在列表中，调用时返回 404。超出权限范围的请求返回 403 `runtime_credential_scope_denied`。未限定范围的密钥可以调用全部接口。

访问记录保留 90 天（部署方可调整），之后自动清理。

## 快速开始

### 1. 获取 App 列表

<CodeGroup title="curl">

```bash
curl '{apibase}/apps' \
  --header 'Authorization: Bearer <runtime-key>'
```

</CodeGroup>

响应中的 `app_key` 即 App ID：

<CodeGroup title="响应示例">

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "items": [
      {
        "app_key": "app_34ab5c8d91ef",
        "name": "研究助手",
        "description": "提供有依据的回答",
        "icon_url": "https://example.com/icon.png",
        "version": "v12",
        "version_uuid": "7b0df140-fbc1-41ef-9234-611172283b23",
        "status": "active",
        "supports_stream": true,
        "file_upload_enabled": true,
        "supports_vision": true,
        "agent_memory_enabled": true,
        "capabilities": ["chat", "conversations", "files", "memory", "vision"]
      }
    ]
  }
}
```

</CodeGroup>

### 2. 发送第一条消息

<CodeGroup title="curl">

```bash
curl -N -X POST '{apibase}/apps/app_34ab5c8d91ef/chat' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"query":"总结这份报告"}'
```

</CodeGroup>

保存 `message_start` 返回的 `conversation_id` 和 `message_id`，用于查询历史、恢复事件流或停止生成。

## Apps

每个外部接入最多开放 500 个 App（智能体和数字人合计，部署方可调整）。获取 App 列表时可传 `page` 和 `limit`（最大 200）分页，响应会带上 `total` 和 `has_more`；不传则返回全部。

<Heading url="/apps" method="GET" title="获取 App 列表" name="#List-Apps" />

返回当前外部接入中可调用的 App（智能体和数字人）。该接口只需要 Runtime Key。

<Heading url="/apps/{app_key}" method="GET" title="获取 App 详情" name="#Get-App" />

只需要 Runtime Key，不需要 External User ID。返回 App 最新发布版本的公开展示信息和当前可用能力。

<Properties>
  <Property name='app_key' type='string' propKey='app_key'>稳定的 App ID。</Property>
  <Property name='name / description' type='string' propKey='name'>App 的公开名称与描述。</Property>
  <Property name='icon / icon_type / icon_url' type='string' propKey='icon_url'>App 图标信息。</Property>
  <Property name='version / version_uuid' type='string' propKey='version'>当前最新发布版本。</Property>
  <Property name='opening_statement' type='string' propKey='opening_statement'>开场白。</Property>
  <Property name='input_placeholder' type='string' propKey='input_placeholder'>输入提示。</Property>
  <Property name='suggested_questions' type='array[string]' propKey='suggested_questions'>建议问题。</Property>
  <Property name='capabilities' type='array[string]' propKey='capabilities'>当前实际可用能力。</Property>
</Properties>

<Heading url="/apps/{app_key}/config" method="GET" title="获取完整发布配置" name="#Get-App-Config" />

只需要 Runtime Key。返回落地页标题、开场白、输入提示、主题色、建议问题、文件/视觉/记忆开关和发布版本。可直接使用这些字段构建外部聊天界面。

<Heading url="/apps/{app_key}/parameters" method="GET" title="获取输入与上传参数" name="#Get-App-Parameters" />

只需要 Runtime Key。返回 `features`、`file_upload`、`agent_memory` 和 `system_parameters`，包括允许文件类型、文档/图片/音频/视频大小限制、上传数量以及记忆是否要求 External User ID。

## Chat 与事件流

<Heading url="/apps/{app_key}/chat" method="POST" title="发送聊天消息" name="#Chat" />

### 请求体

<Properties>
  <Property name='query' type='string' propKey='query'>必填，本轮用户输入。</Property>
  <Property name='conversation_id' type='uuid' propKey='conversation_id'>可选。继续已有会话时传入。</Property>
  <Property name='parent_id' type='uuid' propKey='parent_id'>可选。指定父消息。</Property>
  <Property name='file_ids' type='array[uuid]' propKey='file_ids'>可选。引用当前 External User ID 所拥有的文件；所选智能体未启用文件能力时，文件引用会被服务端过滤。</Property>
  <Property name='response_mode' type='string' propKey='response_mode'>可选，仅支持 `streaming`。</Property>
  <Property name='max_task_tokens' type='integer' propKey='max_task_tokens'>可选。为 Agent 任务设置 Token 预算；耗尽时可能进入 `token_budget_requested` 等待状态。</Property>
</Properties>

### SSE 事件

| event | 说明 |
| --- | --- |
| `message_start` | 返回 conversation、message、模型和标题信息 |
| `message` | 增量文本内容 |
| `agent_progress` / `agent_intermediate_answer` | Agent 执行进度和中间回答 |
| `file_parse_start` / `file_parse_end` / `file_parse_error` | 文件解析状态 |
| `skill_load_start` / `skill_load_end` | Skill 加载状态 |
| `skill_reference_read` | Skill 引用读取状态 |
| `skill_call_start` / `skill_call_end` / `skill_call_error` | Skill 调用状态 |
| `skill_artifact_created` | Skill 生成的产物 |
| `user_input_requested` | Skill 或工作流要求补充输入；根据 `source` 选择对应继续接口 |
| `token_budget_requested` | 任务 Token 预算耗尽；使用事件中的 `request_id` 增加预算或停止 |
| `token_usage_updated` | Token 使用量更新 |
| `message_end` | 消息最终状态和用量；也可能是等待状态 |
| `error` | 安全投影后的错误信息 |

SSE 的 `id` 是可恢复事件游标。断线后通过 events 接口和最后收到的事件 ID 恢复。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/events" method="GET" title="恢复事件流" name="#Resume-Events" />

查询参数可传 `message_id`，请求头可传 `Last-Event-ID`。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/stop" method="POST" title="停止生成" name="#Stop-Conversation" />

停止当前 External User ID 在该 App 会话中的活动生成。

## Conversations

会话按外部接入、External User ID 和 App 隔离。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/apps/{app_key}/conversations` | 分页列出会话 |
| POST | `/apps/{app_key}/conversations` | 创建空会话 |
| GET | `/apps/{app_key}/conversations/search` | 搜索会话和消息 |
| GET | `/apps/{app_key}/conversations/{conversation_id}` | 获取会话 |
| PATCH | `/apps/{app_key}/conversations/{conversation_id}` | 更新标题等字段 |
| DELETE | `/apps/{app_key}/conversations/{conversation_id}` | 删除会话 |
| GET | `/apps/{app_key}/conversations/{conversation_id}/messages` | 分页列出消息 |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/workflow-continuation` | 继续审批或工作流问答 |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/user-input/{request_id}/continue` | 提交 Skill 补充输入并继续 |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/token-budget/{request_id}/continue` | 增加任务 Token 预算或停止任务 |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/resume` | 继续被服务重启中断的 Agent 任务 |

### 创建会话

<CodeGroup title="curl">

```bash
curl -X POST '{apibase}/apps/app_34ab5c8d91ef/conversations' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"title":"季度报告分析"}'
```

</CodeGroup>

会话类型由服务端固定为 `chat`，请求不需要传入 `conversation_type`。使用不同 External User ID 访问同一个会话 ID 时返回 404。

<Heading url="/apps/{app_key}/conversations/search" method="GET" title="搜索会话与消息" name="#Search-Conversations" />

使用 `query` 搜索当前 External User ID 和 App 范围内的会话标题、用户输入与 App 回答。支持 `limit`，不会返回其他用户或其他 App 的结果。

<Heading url="/apps/{app_key}/messages/{message_id}/regenerate" method="POST" title="重新生成根消息" name="#Regenerate-Message" />

按原消息使用的已发布模型和参数重新执行。请求体可选传入新的 `query`；响应为替换同一轮消息的 SSE 流。只允许当前 External User ID 拥有、且满足重新生成条件的消息。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/user-input/{request_id}/continue" method="POST" title="继续 Skill 补充输入" name="#Continue-User-Input" />

请求体为 `{"answers":{"question_id":"answer"}}`。服务端校验 Runtime Subject、App、会话、消息和请求 ID 的归属后，以 SSE 继续同一轮消息。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/workflow-continuation" method="POST" title="继续工作流交互" name="#Continue-Workflow" />

审批使用 `{"type":"approval","approval_token":"...","action":"approve","inputs":{}}`；工作流问答使用 `{"type":"question_answer","inputs":{"query":"..."}}`。响应均为 SSE，且不能跨 External User ID 或 App 继续其他消息。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/token-budget/{request_id}/continue" method="POST" title="继续任务 Token 预算" name="#Continue-Token-Budget" />

从 `token_budget_requested` 事件读取 `request_id`。增加预算时发送 `{"action":"add","additional_tokens":2048}`；终止当前任务时发送 `{"action":"stop"}`。该接口返回同一条消息的 SSE，不使用 `answers` 字段。

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/resume" method="POST" title="继续被中断的任务" name="#Resume-Interrupted-Turn" />

执行 Agent 任务的服务进程中途停止时，消息会以 `status=error`、`error=runtime_lease_expired` 结束。无需请求体调用此接口，即可基于已记录的模型回复和工具结果，以 SSE 继续同一条消息。每条消息只能继续一次，且必须仍是最新的一轮，并且没有可能已产生改动但未记录结果的工具调用；否则流中会返回 code 为 `interrupted_turn_not_resumable` 的 `error` 事件。数字人应用会自行恢复运行，不提供此接口。

## Files

文件按外部接入和 External User ID 隔离，同一用户可以在多个已添加的 App 中使用同一批文件。删除所属工作空间后，文件会立即停止访问，存储对象保留 30 天后由系统定期清理。

<Heading url="/files" method="POST" title="上传文件" name="#Upload-File" />

使用 `multipart/form-data`，文件字段名固定为 `file`。

<CodeGroup title="curl">

```bash
curl -X POST '{apibase}/files' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --form 'file=@./report.pdf'
```

</CodeGroup>

<Heading url="/files" method="GET" title="列出文件" name="#List-Files" />

支持 `page` 和 `limit`，`limit` 最大为 100。

<Heading url="/files/{file_id}" method="GET" title="获取文件元数据" name="#Get-File" />

只返回公开文件元数据：id、name、size、extension、mime_type、created_at。

<Heading url="/files/{file_id}/download-url" method="GET" title="获取下载地址" name="#Download-File" />

授权通过后返回短期签名 URL。

<Heading url="/files/{file_id}" method="DELETE" title="删除文件" name="#Delete-File" />

删除只影响当前 External User ID 拥有的文件。

## Memory

记忆按外部接入、External User ID 和 App 隔离。不同 App 不共享记忆。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/apps/{app_key}/memory` | 获取全部记忆 |
| GET | `/apps/{app_key}/memory/export` | 导出记忆 JSON |
| PUT | `/apps/{app_key}/memory/{key}` | 创建或更新一个记忆值 |
| DELETE | `/apps/{app_key}/memory/{key}` | 删除一个记忆值 |
| DELETE | `/apps/{app_key}/memory` | 清空该用户在当前 App 中的记忆 |
| GET | `/apps/{app_key}/memory/settings` | 获取记忆设置和配置 revision |
| PATCH | `/apps/{app_key}/memory/settings` | 更新记忆和自动捕获设置 |
| POST | `/apps/{app_key}/memory/operations/{operation_id}/undo` | 撤销一次可撤销记忆操作 |

### 更新记忆

<CodeGroup title="curl">

```bash
curl -X PUT '{apibase}/apps/app_34ab5c8d91ef/memory/preference' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Idempotency-Key: 9452d78a-089c-4b19-8aa8-c31ac8419816' \
  --header 'If-Match: 3' \
  --header 'Content-Type: application/json' \
  --data '{"content":"偏好简洁回答"}'
```

</CodeGroup>

`expected_revision` 也可以放在 JSON 请求体中。Revision 不匹配时返回 409，客户端应重新读取后再决定是否重试。

<Heading url="/apps/{app_key}/memory/settings" method="GET / PATCH" title="读取或更新记忆设置" name="#Memory-Settings" />

GET 返回当前记忆开关、自动捕获开关、可写槽位和配置 revision。PATCH 可以更新 `memory_enabled`、`auto_capture_enabled`，并使用 `expected_revision` 防止覆盖并发修改。设置只影响当前 External User ID 与当前 App 的记忆关系。

<Heading url="/apps/{app_key}/memory/operations/{operation_id}/undo" method="POST" title="撤销记忆操作" name="#Undo-Memory" />

`operation_id` 必须来自当前用户、当前 App 的记忆写入或删除响应，并且仍处于可撤销窗口。重复撤销、过期操作或其他用户的操作会返回安全错误，不会影响现有记忆。

## 终端用户

携带过某个 External User ID 的请求之后，或业务后端用 `PATCH` 修改过它之后，该 ID 就是一个终端用户。用 Runtime Key 按业务后端发送的 External User ID 管理终端用户；这些接口不需要 `X-ZGI-External-User-ID` 请求头。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/end-users/{user}` | 查看状态、额度，以及最近 24 小时、7 天、30 天的积分用量（总计和按 App） |
| PATCH | `/end-users/{user}` | 停用或恢复该终端用户，设置套餐，或为其单独设置额度 |
| POST | `/end-users/{user}/export` | 为该终端用户的全部数据创建导出任务，返回 `202` 和任务 |
| GET | `/end-users/{user}/exports/{export_id}` | 查看导出任务状态：`pending`、`running`、`succeeded` 或 `failed` |
| GET | `/end-users/{user}/exports/{export_id}/download` | 下载已完成的导出（JSON 文件） |
| DELETE | `/end-users/{user}` | 在所有 App 中删除该终端用户 |
| GET | `/plans` | 列出控制台定义的套餐及其限额 |
| GET | `/end-users/{user}/entitlement` | 当前权益：套餐、各窗口的用量、限额、剩余和最早用量移出窗口的时间、积分余额，以及能否发起新的运行 |
| GET | `/end-users/{user}/credits` | 积分余额和流水 |
| POST | `/end-users/{user}/credits` | 发放或扣回积分 |

<CodeGroup title="为终端用户单独设置额度">

```bash
curl -X PATCH '{apibase}/end-users/customer-42' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'Content-Type: application/json' \
  --data '{"quota":{"limits":[{"window":"24h","points":50}]}}'
```

</CodeGroup>

<CodeGroup title="用户付费后设置套餐">

```bash
curl -X PATCH '{apibase}/end-users/customer-42'   --header 'Authorization: Bearer <runtime-key>'   --header 'Content-Type: application/json'   --data '{"plan":{"key":"pro","expires_at":"2026-12-31T23:59:59Z"}}'
```

</CodeGroup>

- `plan` 为终端用户设置控制台定义的套餐：`{"key": "...", "expires_at": "..."}`，`expires_at` 可省略，表示长期有效。套餐的限额替代默认限额，到期后自动恢复默认限额，无需再次调用。`"plan": null` 表示移除套餐。可以在终端用户首次发起请求之前设置。
- `status` 取值为 `active` 或 `suspended`。停用后仍可读取对话、文件和记忆，但发起新的对话或运行会返回 403 `end_user.suspended`。
- `quota` 替代控制台为每个终端用户设置的限额：`{"limits": [...]}`，窗口为 `24h`、`7d` 或 `30d`，积分最小 0.001；或 `{"unlimited": true}`。单个 App 的额外上限仍然生效。单独额度优先于套餐。`"quota": null` 表示恢复使用套餐或控制台限额。
- 终端用户超出额度后，发起对话或运行会返回 429 `quota.exceeded`，直到窗口内用量回落到限额以下，或其积分余额为正。错误本身不带详情；需要时读取 `entitlement` 向用户展示剩余额度，并引导升级或充值。

<CodeGroup title="用户充值后发放积分">

```bash
curl -X POST '{apibase}/end-users/customer-42/credits' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'Content-Type: application/json' \
  --data '{"points":100,"external_id":"order-20261024-001","reason":"top-up","expires_at":"2027-10-24T00:00:00Z"}'
```

</CodeGroup>

- `external_id` 必填，建议使用业务订单号：同一 `external_id` 重复提交只记录一次，换一个金额则返回 409 `runtime_credit_conflict`。`points` 为负数表示扣回（不能带 `expires_at`）。
- 超出限额的用量从积分中扣除，先扣最早到期的积分；积分不抵扣单个 App 的上限。没有限额（或单独额度为不限）的终端用户不会消耗积分。把限额设为 0 表示不含额度，所有用量都从积分扣除，即按量付费。
- 用量在每次模型调用后结算，余额可能因进行中的调用略低于 0；欠额会在下次发放时先抵扣。只统计首次发放积分之后的用量。
- 导出在后台执行：`POST` 返回任务，已有进行中的任务时直接返回它；轮询任务直到 `succeeded`，再下载。未完成时下载返回 409 `runtime_export_not_ready`。导出内容包括全部对话及消息、记忆、上传文件信息，以及数字人实例、实例记忆、运行、任务、报告、通知和产物，不会截断。压缩后超过 64 MB 的导出会失败并给出原因。导出保留 7 天；删除终端用户时一并删除。
- 删除会在所有 App 中删除上述数据，之后 `GET` 返回状态为 `erased`、不含 External User ID 的记录。用量和审计记录仅保留标识。之后使用相同 External User ID 的请求会作为一个新的空白终端用户。

### Webhook 事件

在控制台「额度与用量」页配置接收地址后，平台会向业务系统 `POST` 以下事件（JSON）：

| 事件 | 触发时机 |
| --- | --- |
| `quota.near` | 任一窗口用量达到限额的 80%（每个窗口周期最多一次） |
| `quota.exceeded` | 任一窗口用量达到限额，包括单个 App 的上限（每个窗口周期最多一次） |
| `credits.low` | 积分余额降到设定阈值或以下 |
| `plan.expired` | 套餐到期 |

<CodeGroup title="请求体示例">

```json
{"id": "…", "event": "quota.near", "created_at": "2026-10-24T12:00:00Z", "runtime_workspace_id": "…",
 "data": {"user": "customer-42", "subject_id": "…", "window": "24h", "points": 8.5, "limit": 10}}
```

</CodeGroup>

- 请求头：`X-ZGI-Event`、`X-ZGI-Delivery`（与 `id` 相同）、`X-ZGI-Timestamp`（Unix 秒）、`X-ZGI-Signature: sha256=<hex>`。
- 校验：用创建时显示的密钥对 `<timestamp>.<原始请求体>` 计算 HMAC-SHA256，与签名常量时间比较，并拒绝超过 5 分钟的时间戳。
- 返回任意 2xx 视为送达；否则按 30 秒起指数退避重试，最多 8 次。同一事件可能重复送达，请按 `X-ZGI-Delivery` 去重。

### 终端用户连接

数字人可以配置**按用户**的连接器：这类操作以终端用户本人的身份、用其本人的 key 执行，而不是以数字人的身份。由你的业务后端为终端用户提交 key。key 只写入、不可读取，任何响应都不会返回或回显。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/end-users/{user}/connections` | 查看各数字人 App 按用户连接的状态：`connected`、`needs_connection` 或 `reconnect_required` |
| POST | `/end-users/{user}/connections` | 校验并连接一个连接项：`{"app_key", "slot_key", "values": {...}}`，需携带 `Idempotency-Key` 请求头（16–200 个字符，建议使用 UUID） |
| DELETE | `/end-users/{user}/connections/{app_key}/{slot_key}` | 断开该连接项，并销毁已保存的 key |

- key 校验失败返回 400，并给出连接器错误码，例如 `connector_key_invalid`。
- 连接之前，数字人会提示终端用户先连接自己的账号，不会改用其他账号代替。
- 删除终端用户时，其连接也会一并销毁。

### 连接器操作确认

会改动外部系统的操作需要确认，只读操作直接执行。需要确认时运行会暂停，消息处于待审批状态，由发起这次运行的终端用户决定：

`POST /apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/connector-confirmation`，请求体为 `{"decision": "confirmed" | "cancelled"}`

响应中的 `state` 为执行结果：`completed`、`cancelled`、`failed` 或 `unknown`。

## Key 轮换

每个外部接入最多有 50 个可用 Key，已撤销或过期的 Key 不计入。推荐顺序：

1. 在控制台创建新 Runtime Key。
2. 将新 Key 部署到业务服务端。
3. 使用新 Key 验证 Apps、Chat、文件和记忆接口。
4. 撤销旧 Key。

Key 轮换不会改变 App ID、External User ID 派生的 Subject、文件、会话或记忆归属。

## 错误处理

错误响应格式：

<CodeGroup title="错误响应示例">

```json
{
  "code": "401001",
  "message": "Please login first"
}
```

</CodeGroup>

| HTTP 状态 | 处理建议 |
| --- | --- |
| 400 | 校验请求参数和请求体 |
| 401 | 检查 Runtime Key 是否缺失、过期或已撤销 |
| 403 | 检查外部接入或 App 状态；`end_user.suspended` 表示该终端用户已被停用；`runtime_credential_scope_denied` 表示密钥的权限范围不包含该接口 |
| 404 | 资源不存在，或不属于当前 External User ID |
| 409 | 重新读取 revision，或检查幂等请求 |
| 413 | 根据上传限制缩小文件 |
| 429 | 按 `Retry-After` 退避重试；`quota.exceeded` 表示该终端用户的额度已用完；`runtime_end_user_rate_limited` 表示该终端用户请求过于频繁 |
| 500 | 使用相同幂等键重试安全写操作，并记录 request ID |

所有响应都会携带 `X-Request-ID`。向运维人员反馈问题时请提供该值，不要提供完整 Runtime Key。
