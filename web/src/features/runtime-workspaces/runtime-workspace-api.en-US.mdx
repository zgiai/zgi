## Integration overview

### Base URL

<CodeGroup title="Base URL">

```text
{apibase}
```

</CodeGroup>

### Core identifiers

| Name | Purpose | Handling |
| --- | --- | --- |
| Runtime Key | Authenticates every request to this external access | Keep secret |
| App ID | Selects the App (assistant or digital human) in an API path | May be public |
| External User ID | Identifies the business end user and scopes files, conversations, and memory | Use an opaque value without personal information |

App IDs are generated by ZGI and remain stable when an App is republished or Runtime Keys are rotated.

### Common headers

<Properties>
  <Property name='Authorization' type='string' propKey='Authorization'>Required. Use `Bearer {'<runtime-key>'}`.</Property>
  <Property name='X-ZGI-External-User-ID' type='string' propKey='X-ZGI-External-User-ID'>Required for App, file, conversation, and memory operations. Send a stable, opaque, case-sensitive identifier containing 1–128 Unicode characters.</Property>
  <Property name='Content-Type' type='string' propKey='Content-Type'>Use `application/json` for JSON requests.</Property>
  <Property name='Idempotency-Key' type='uuid' propKey='Idempotency-Key'>Optional for memory mutations. Reuse the same value when retrying the same operation.</Property>
  <Property name='If-Match' type='integer' propKey='If-Match'>Current memory revision for concurrency-safe updates and deletes.</Property>
</Properties>

Keep Runtime Keys in a trusted server environment. Browser and mobile applications should call ZGI through your backend or BFF.

Administrators can set a `requests_per_minute` policy for external access. Limited requests return `429` with `Retry-After`, `X-RateLimit-Limit`, and `X-RateLimit-Remaining`; clients should back off until the window resets.

## Quick start

### 1. List Apps

<CodeGroup title="curl">

```bash
curl '{apibase}/apps' \
  --header 'Authorization: Bearer <runtime-key>'
```

</CodeGroup>

The `app_key` value is the App ID:

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "items": [
      {
        "app_key": "app_34ab5c8d91ef",
        "name": "Research Assistant",
        "description": "Provides evidence-backed answers",
        "icon_url": "https://example.com/icon.png",
        "version": "v12",
        "version_uuid": "7b0df140-fbc1-41ef-9234-611172283b23",
        "status": "active",
        "supports_stream": true,
        "file_upload_enabled": true,
        "supports_vision": true,
        "agent_memory_enabled": true,
        "capabilities": ["chat", "conversations", "files", "memory", "vision"]
      }
    ]
  }
}
```

### 2. Send a message

<CodeGroup title="curl">

```bash
curl -N -X POST '{apibase}/apps/app_34ab5c8d91ef/chat' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"query":"Summarize this report"}'
```

</CodeGroup>

Persist the `conversation_id` and `message_id` from `message_start` to query history, resume events, or stop generation.

| Event | Meaning |
| --- | --- |
| `message_start` | Conversation, message, title, and model identity |
| `message` | Incremental answer text |
| `agent_progress` / `agent_intermediate_answer` | Agent progress and intermediate answers |
| `file_parse_start` / `file_parse_end` / `file_parse_error` | File parsing state |
| `skill_load_start` / `skill_load_end` | Skill loading state |
| `skill_reference_read` | Skill reference reads |

## Conversations

Conversations are scoped by external access, External User ID, and App.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/apps/{app_key}/conversations` | List conversations |
| POST | `/apps/{app_key}/conversations` | Create a conversation |
| GET | `/apps/{app_key}/conversations/search` | Search conversations and messages |
| GET | `/apps/{app_key}/conversations/{conversation_id}` | Get a conversation |
| PATCH | `/apps/{app_key}/conversations/{conversation_id}` | Update a conversation |
| DELETE | `/apps/{app_key}/conversations/{conversation_id}` | Delete a conversation |
| GET | `/apps/{app_key}/conversations/{conversation_id}/messages` | List messages |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/workflow-continuation` | Continue an approval or workflow question |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/user-input/{request_id}/continue` | Submit Skill input and continue |
| POST | `/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/token-budget/{request_id}/continue` | Add task tokens or stop the task |

<CodeGroup title="Create a conversation">

```bash
curl -X POST '{apibase}/apps/app_34ab5c8d91ef/conversations' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"title":"Quarterly report analysis"}'
```

</CodeGroup>

The server always creates `chat` conversations; callers do not send `conversation_type`. A different External User ID receives 404 for the same conversation ID.

<Heading url="/apps/{app_key}/conversations/search" method="GET" title="Search conversations and messages" name="#Search-Conversations" />

Use `query` to search titles, user inputs, and App answers within the current External User ID and App scope.

<Heading url="/apps/{app_key}/messages/{message_id}/regenerate" method="POST" title="Regenerate a root message" name="#Regenerate-Message" />

Re-executes the root message with the original published model and parameters. An optional `query` replaces the original input; the response is a replacement SSE stream for the same turn.

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/user-input/{request_id}/continue" method="POST" title="Continue Skill user input" name="#Continue-User-Input" />

Send `{"answers":{"question_id":"answer"}}`. After validating the Runtime Subject, App, conversation, message, and request ownership, the server resumes the same message as an SSE stream.

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/workflow-continuation" method="POST" title="Continue a workflow interaction" name="#Continue-Workflow" />

For approvals, send `{"type":"approval","approval_token":"...","action":"approve","inputs":{}}`. For workflow questions, send `{"type":"question_answer","inputs":{"query":"..."}}`. Both return SSE and remain scoped to the current External User ID and App.

<Heading url="/apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/token-budget/{request_id}/continue" method="POST" title="Continue a task token budget" name="#Continue-Token-Budget" />

Read `request_id` from `token_budget_requested`. Send `{"action":"add","additional_tokens":2048}` to add budget, or `{"action":"stop"}` to terminate the current task. The response continues the same message as SSE and does not accept `answers`.

## Files

Files are scoped by external access and External User ID. One user can reuse the same files across exposed Apps. Deleting the owning Workspace makes them unavailable immediately; stored objects are retained for 30 days and then removed by the scheduled cleanup.

<Heading url="/files" method="POST" title="Upload a file" name="#Upload-File" />

Send `multipart/form-data` with a `file` field.

<CodeGroup title="curl">

```bash
curl -X POST '{apibase}/files' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --form 'file=@./report.pdf'
```

</CodeGroup>

<Heading url="/files" method="GET" title="List files" name="#List-Files" />

Supports `page` and `limit`; maximum `limit` is 100.

<Heading url="/files/{file_id}" method="GET" title="Get file metadata" name="#Get-File" />

Returns id, name, size, extension, mime_type, and created_at.

<Heading url="/files/{file_id}/download-url" method="GET" title="Get a download URL" name="#Download-File" />

Returns a short-lived signed URL after ownership validation.

<Heading url="/files/{file_id}" method="DELETE" title="Delete a file" name="#Delete-File" />

Deletes a file owned by the current External User ID.

## Memory

Memory is scoped by external access, External User ID, and App. Different Apps keep separate memories.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/apps/{app_key}/memory` | Read all memory values |
| GET | `/apps/{app_key}/memory/export` | Export memory JSON |
| PUT | `/apps/{app_key}/memory/{key}` | Create or update a value |
| DELETE | `/apps/{app_key}/memory/{key}` | Delete a value |
| DELETE | `/apps/{app_key}/memory` | Clear memory for this user and App |
| GET | `/apps/{app_key}/memory/settings` | Get memory settings and configuration revision |
| PATCH | `/apps/{app_key}/memory/settings` | Update memory and automatic capture settings |
| POST | `/apps/{app_key}/memory/operations/{operation_id}/undo` | Undo an eligible memory operation |

<CodeGroup title="Update memory">

```bash
curl -X PUT '{apibase}/apps/app_34ab5c8d91ef/memory/preference' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Idempotency-Key: 9452d78a-089c-4b19-8aa8-c31ac8419816' \
  --header 'If-Match: 3' \
  --header 'Content-Type: application/json' \
  --data '{"content":"Prefers concise answers"}'
```

</CodeGroup>

You may send `expected_revision` in the JSON body instead. A stale revision returns 409; read the current value before deciding whether to retry.

<Heading url="/apps/{app_key}/memory/settings" method="GET / PATCH" title="Read or update memory settings" name="#Memory-Settings" />

GET returns memory, automatic capture, writable slots, and configuration revision. PATCH updates `memory_enabled` or `auto_capture_enabled` with optional revision protection for the current External User ID and App relationship.

<Heading url="/apps/{app_key}/memory/operations/{operation_id}/undo" method="POST" title="Undo a memory operation" name="#Undo-Memory" />

The operation must belong to the current External User ID and App and remain inside its undo window. Repeated, expired, or foreign operations fail safely.

## End users

An end user is an External User ID that has made at least one request, or that your backend has changed with `PATCH`. Manage them with the Runtime Key, addressing each by the External User ID your backend sends; these calls need no `X-ZGI-External-User-ID` header.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/end-users/{user}` | Status, quota, and points used over the last 24 hours, 7 days, and 30 days, in total and per App |
| PATCH | `/end-users/{user}` | Suspend or resume the end user, set their plan, or set their own quota |
| POST | `/end-users/{user}/export` | Export everything kept for the end user as one JSON document |
| DELETE | `/end-users/{user}` | Erase the end user from every App |
| GET | `/plans` | The plans defined in the console, with their limits |
| GET | `/end-users/{user}/entitlement` | What the end user may spend now: plan, each window's usage, limit, remaining points and when its oldest usage leaves the window, the credit balance, and whether a new run would be admitted |
| GET | `/end-users/{user}/credits` | Credit balance and ledger |
| POST | `/end-users/{user}/credits` | Grant or take back credits |

<CodeGroup title="Give an end user their own quota">

```bash
curl -X PATCH '{apibase}/end-users/customer-42' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'Content-Type: application/json' \
  --data '{"quota":{"limits":[{"window":"24h","points":50}]}}'
```

</CodeGroup>

<CodeGroup title="Set a plan after a purchase">

```bash
curl -X PATCH '{apibase}/end-users/customer-42'   --header 'Authorization: Bearer <runtime-key>'   --header 'Content-Type: application/json'   --data '{"plan":{"key":"pro","expires_at":"2026-12-31T23:59:59Z"}}'
```

</CodeGroup>

- `plan` gives the end user a plan defined in the console: `{"key": "...", "expires_at": "..."}`; leave out `expires_at` for no expiry. The plan's limits replace the default limits, and the defaults apply again once it expires, with no further call. `"plan": null` removes it. You can set a plan before the end user's first request.
- `status` is `active` or `suspended`. A suspended end user can still read conversations, files, and memory, but new chats and runs return 403 `end_user.suspended`.
- `quota` replaces the console's per-end-user limits for this end user: `{"limits": [...]}` with windows `24h`, `7d`, or `30d` and points down to 0.001, or `{"unlimited": true}`. Caps set for single Apps still apply. An own quota takes precedence over a plan. `"quota": null` returns the end user to their plan or the console's limits.
- An end user over a quota gets 429 `quota.exceeded` when starting a chat or run, until usage in the window falls below the limit or their credit balance is positive. The error carries no details; read `entitlement` to show what remains and offer an upgrade or a top-up.

<CodeGroup title="Grant credits after a top-up">

```bash
curl -X POST '{apibase}/end-users/customer-42/credits' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'Content-Type: application/json' \
  --data '{"points":100,"external_id":"order-20261024-001","reason":"top-up","expires_at":"2027-10-24T00:00:00Z"}'
```

</CodeGroup>

- `external_id` is required; use your order ID. Sending the same `external_id` again records the grant once; another amount returns 409 `runtime_credit_conflict`. Negative `points` take credits back (without `expires_at`).
- Usage beyond the limits is paid with credits, soonest expiry first; credits do not lift per-App caps. End users without limits (or with an own quota of no limit) never spend credits. A limit of 0 includes nothing, so all usage is paid with credits: pay as you go.
- Usage is settled after each model call, so a balance can dip below 0 by the calls in progress; the next grant pays the debt first. Only usage after the first grant is charged.
- Export returns conversations with their messages, memory, uploaded file details, and DigitalHuman instances, instance memory, runs, tasks, reports, notifications, and artifacts. Large histories are capped and marked `truncated`.
- Erasure deletes all of that in every App, and `GET` then returns the end user with status `erased` and no External User ID. Usage and audit records keep identifiers only. A later request with the same External User ID starts a new, empty end user.

### Webhook events

Once an endpoint is set up on the console's Quotas & usage page, these events are `POST`ed to your server as JSON:

| Event | When |
| --- | --- |
| `quota.near` | Usage in a window reaches 80% of a limit (at most once per window) |
| `quota.exceeded` | Usage in a window reaches a limit, per-App caps included (at most once per window) |
| `credits.low` | The credit balance falls to the threshold you set or below |
| `plan.expired` | A plan expires |

```json
{"id": "…", "event": "quota.near", "created_at": "2026-10-24T12:00:00Z", "runtime_workspace_id": "…",
 "data": {"user": "customer-42", "subject_id": "…", "window": "24h", "points": 8.5, "limit": 10}}
```

- Headers: `X-ZGI-Event`, `X-ZGI-Delivery` (the same as `id`), `X-ZGI-Timestamp` (Unix seconds), `X-ZGI-Signature: sha256=<hex>`.
- To verify, compute HMAC-SHA256 of `<timestamp>.<raw body>` with the secret shown when the webhook was created, compare it to the signature in constant time, and reject timestamps older than 5 minutes.
- Any 2xx counts as delivered; otherwise the event is retried with exponential backoff from 30 seconds, up to 8 times. An event may arrive more than once; deduplicate by `X-ZGI-Delivery`.

### End-user connections

A DigitalHuman may have **per-user** Connector slots: an operation that acts as the end user, with the end user's own key, instead of as the DigitalHuman. Your backend supplies that key. Keys are write-only, and no response ever returns or repeats one.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/end-users/{user}/connections` | Per-user slots of each DigitalHuman App and their state: `connected`, `needs_connection`, or `reconnect_required` |
| POST | `/end-users/{user}/connections` | Verify a key for one slot and connect it: `{"app_key", "slot_key", "values": {...}}`, with an `Idempotency-Key` header |
| DELETE | `/end-users/{user}/connections/{app_key}/{slot_key}` | Disconnect the slot and destroy the stored key |

- A key that fails verification returns 400 with a connector error code such as `connector_key_invalid`.
- Until a slot is connected, the DigitalHuman tells the end user to connect their own account and never uses another one in its place.
- Erasing the end user also destroys their connections.

### Connector confirmations

An operation that changes something in a connected system waits for confirmation. Read operations run without one. The run then stops, and the message is waiting for approval. The end user who started the run decides:

`POST /apps/{app_key}/conversations/{conversation_id}/messages/{message_id}/connector-confirmation` with `{"decision": "confirmed" | "cancelled"}`

The response carries the resulting `state`: `completed`, `cancelled`, `failed`, or `unknown`.

## Runtime Key rotation

1. Create a new Runtime Key in the console.
2. Deploy it to the calling backend.
3. Verify Apps, Chat, file, and memory calls.
4. Revoke the old Key.

Rotation does not change App IDs, Subjects, files, conversations, or memory ownership.

## Error handling

```json
{
  "code": "401001",
  "message": "Please login first"
}
```

| HTTP status | Recommended action |
| --- | --- |
| 400 | Validate parameters and request body |
| 401 | Check whether the Runtime Key is missing, expired, or revoked |
| 403 | Check the external access and App status; `end_user.suspended` means the end user is suspended |
| 404 | The resource does not exist or is owned by another External User ID |
| 409 | Refresh the revision or inspect the idempotent operation |
| 413 | Reduce file size |
| 429 | Retry according to `Retry-After`; `quota.exceeded` means the end user has spent a quota |
| 500 | Retry safe mutations with the same idempotency key and retain the request ID |

Responses include `X-Request-ID`. Share that value with operators without sharing the Runtime Key.
