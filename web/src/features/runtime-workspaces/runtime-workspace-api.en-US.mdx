# Runtime Workspace API

Use one or more rotatable Runtime Keys to call multiple published Agents exposed by the current Runtime Workspace.

## Integration overview

### Base URL

<CodeGroup title="Base URL">

```text
{apibase}
```

</CodeGroup>

### Core identifiers

| Name | Purpose | Handling |
| --- | --- | --- |
| Runtime Key | Authenticates every request for one Runtime Workspace | Keep secret |
| App ID | Selects the Agent in an API path | May be public |
| External User ID | Identifies the business end user and scopes files, conversations, and memory | Use an opaque value without personal information |

App IDs are generated by ZGI and remain stable when an Agent is republished or Runtime Keys are rotated.

### Common headers

<Properties>
  <Property name='Authorization' type='string' propKey='Authorization'>Required. Use `Bearer {'<runtime-key>'}`.</Property>
  <Property name='X-ZGI-External-User-ID' type='string' propKey='X-ZGI-External-User-ID'>Required for App, file, conversation, and memory operations. Send a stable, opaque, case-sensitive identifier containing 1–128 Unicode characters.</Property>
  <Property name='Content-Type' type='string' propKey='Content-Type'>Use `application/json` for JSON requests.</Property>
  <Property name='Idempotency-Key' type='uuid' propKey='Idempotency-Key'>Optional for memory mutations. Reuse the same value when retrying the same operation.</Property>
  <Property name='If-Match' type='integer' propKey='If-Match'>Current memory revision for concurrency-safe updates and deletes.</Property>
</Properties>

Keep Runtime Keys in a trusted server environment. Browser and mobile applications should call ZGI through your backend or BFF.

A Runtime Workspace can configure a `requests_per_minute` policy. Limited requests return `429` with `Retry-After`, `X-RateLimit-Limit`, and `X-RateLimit-Remaining`; clients should back off until the window resets.

## Quick start

### 1. List Apps

<CodeGroup title="curl">

```bash
curl '{apibase}/apps' \
  --header 'Authorization: Bearer <runtime-key>'
```

</CodeGroup>

The `app_key` value is the App ID:

```json
{
  "code": "0",
  "message": "success",
  "data": {
    "items": [
      {
        "app_key": "app_34ab5c8d91ef",
        "name": "Research Assistant",
        "description": "Provides evidence-backed answers",
        "icon_url": "https://example.com/icon.png",
        "version": "v12",
        "version_uuid": "7b0df140-fbc1-41ef-9234-611172283b23",
        "status": "active",
        "supports_stream": true,
        "file_upload_enabled": true,
        "supports_vision": true,
        "agent_memory_enabled": true,
        "capabilities": ["chat", "conversations", "files", "memory", "vision"]
      }
    ]
  }
}
```

### 2. Send a message

<CodeGroup title="curl">

```bash
curl -N -X POST '{apibase}/apps/app_34ab5c8d91ef/chat' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"query":"Summarize this report"}'
```

</CodeGroup>

Persist the `conversation_id` and `message_id` from `message_start` to query history, resume events, or stop generation.

## Apps

<Heading url="/apps" method="GET" title="List Apps" name="#List-Apps" />

Returns callable Agents exposed by the authenticated Runtime Workspace. This endpoint only requires the Runtime Key.

<Heading url="/apps/{app_key}" method="GET" title="Get App details" name="#Get-App" />

Requires only the Runtime Key, not an External User ID. The response contains the latest published public presentation and effective capabilities.

<Properties>
  <Property name='app_key' type='string' propKey='app_key'>Stable App ID.</Property>
  <Property name='name / description' type='string' propKey='name'>Published Agent presentation.</Property>
  <Property name='icon / icon_type / icon_url' type='string' propKey='icon_url'>Agent icon fields.</Property>
  <Property name='version / version_uuid' type='string' propKey='version'>Latest published version.</Property>
  <Property name='opening_statement' type='string' propKey='opening_statement'>Opening message.</Property>
  <Property name='input_placeholder' type='string' propKey='input_placeholder'>Input guidance.</Property>
  <Property name='suggested_questions' type='array[string]' propKey='suggested_questions'>Suggested prompts.</Property>
  <Property name='capabilities' type='array[string]' propKey='capabilities'>Capabilities currently available through this App.</Property>
</Properties>

<Heading url="/apps/{app_key}/config" method="GET" title="Get the complete published configuration" name="#Get-App-Config" />

Requires only the Runtime Key. Returns presentation fields, feature switches, memory requirements, and published version information for building an external chat UI.

<Heading url="/apps/{app_key}/parameters" method="GET" title="Get input and upload parameters" name="#Get-App-Parameters" />

Returns presentation features, allowed file types, document/image/audio/video size limits, upload count, vision support, and memory requirements.

## Chat and event streams

<Heading url="/apps/{app_key}/chat" method="POST" title="Send a chat message" name="#Chat" />

### Request body

<Properties>
  <Property name='query' type='string' propKey='query'>Required user input.</Property>
  <Property name='conversation_id' type='uuid' propKey='conversation_id'>Optional existing conversation.</Property>
  <Property name='parent_id' type='uuid' propKey='parent_id'>Optional parent message.</Property>
  <Property name='file_ids' type='array[uuid]' propKey='file_ids'>Files owned by the current External User ID. The server filters these references when the selected assistant has file input disabled.</Property>
  <Property name='response_mode' type='string' propKey='response_mode'>Optional; use `streaming`.</Property>
  <Property name='max_task_tokens' type='integer' propKey='max_task_tokens'>Optional Agent task budget. Exhaustion may emit `token_budget_requested`.</Property>
</Properties>

### SSE events

| Event | Meaning |
| --- | --- |
| `message_start` | Conversation, message, title, and model identity |
| `message` | Incremental answer text |
| `agent_progress` / `agent_intermediate_answer` | Agent progress and intermediate answers |
| `file_parse_start` / `file_parse_end` / `file_parse_error` | File parsing state |
| `skill_load_start` / `skill_load_end` | Skill loading state |
| `skill_reference_read` | Skill reference reads |
| `skill_call_start` / `skill_call_end` / `skill_call_error` | Skill execution state |
| `skill_artifact_created` | Skill-generated artifacts |
| `token_usage_updated` | Updated token usage |
| `message_end` | Final or waiting message state and usage |
| `error` | Safe public error projection |

Each SSE `id` is a resumable cursor.

<Heading url="/apps/{app_key}/conversations/{conversation_id}/events" method="GET" title="Resume events" name="#Resume-Events" />

Use `message_id` and optionally send `Last-Event-ID`.

<Heading url="/apps/{app_key}/conversations/{conversation_id}/stop" method="POST" title="Stop generation" name="#Stop-Conversation" />

Stops the active generation owned by the current External User ID and Agent.

## Conversations

Conversations are scoped by Runtime Workspace, External User ID, and Agent.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/apps/{app_key}/conversations` | List conversations |
| POST | `/apps/{app_key}/conversations` | Create a conversation |
| GET | `/apps/{app_key}/conversations/search` | Search conversations and messages |
| GET | `/apps/{app_key}/conversations/{conversation_id}` | Get a conversation |
| PATCH | `/apps/{app_key}/conversations/{conversation_id}` | Update a conversation |
| DELETE | `/apps/{app_key}/conversations/{conversation_id}` | Delete a conversation |
| GET | `/apps/{app_key}/conversations/{conversation_id}/messages` | List messages |

<CodeGroup title="Create a conversation">

```bash
curl -X POST '{apibase}/apps/app_34ab5c8d91ef/conversations' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Content-Type: application/json' \
  --data '{"title":"Quarterly report analysis"}'
```

</CodeGroup>

The server always creates `chat` conversations; callers do not send `conversation_type`. A different External User ID receives 404 for the same conversation ID.

<Heading url="/apps/{app_key}/conversations/search" method="GET" title="Search conversations and messages" name="#Search-Conversations" />

Use `query` to search titles, user inputs, and Agent answers within the current External User ID and App scope.

<Heading url="/apps/{app_key}/messages/{message_id}/regenerate" method="POST" title="Regenerate a root message" name="#Regenerate-Message" />

Re-executes the root message with the original published model and parameters. An optional `query` replaces the original input; the response is a replacement SSE stream for the same turn.

## Files

Files are scoped by Runtime Workspace and External User ID. One user can reuse the same files across exposed Agents.

<Heading url="/files" method="POST" title="Upload a file" name="#Upload-File" />

Send `multipart/form-data` with a `file` field.

<CodeGroup title="curl">

```bash
curl -X POST '{apibase}/files' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --form 'file=@./report.pdf'
```

</CodeGroup>

<Heading url="/files" method="GET" title="List files" name="#List-Files" />

Supports `page` and `limit`; maximum `limit` is 100.

<Heading url="/files/{file_id}" method="GET" title="Get file metadata" name="#Get-File" />

Returns id, name, size, extension, mime_type, and created_at.

<Heading url="/files/{file_id}/download-url" method="GET" title="Get a download URL" name="#Download-File" />

Returns a short-lived signed URL after ownership validation.

<Heading url="/files/{file_id}" method="DELETE" title="Delete a file" name="#Delete-File" />

Deletes a file owned by the current External User ID.

## Memory

Memory is scoped by Runtime Workspace, External User ID, and Agent. Different Agents keep separate memories.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/apps/{app_key}/memory` | Read all memory values |
| GET | `/apps/{app_key}/memory/export` | Export memory JSON |
| PUT | `/apps/{app_key}/memory/{key}` | Create or update a value |
| DELETE | `/apps/{app_key}/memory/{key}` | Delete a value |
| DELETE | `/apps/{app_key}/memory` | Clear memory for this user and Agent |
| GET | `/apps/{app_key}/memory/settings` | Get memory settings and configuration revision |
| PATCH | `/apps/{app_key}/memory/settings` | Update memory and automatic capture settings |
| POST | `/apps/{app_key}/memory/operations/{operation_id}/undo` | Undo an eligible memory operation |

<CodeGroup title="Update memory">

```bash
curl -X PUT '{apibase}/apps/app_34ab5c8d91ef/memory/preference' \
  --header 'Authorization: Bearer <runtime-key>' \
  --header 'X-ZGI-External-User-ID: customer-42' \
  --header 'Idempotency-Key: 9452d78a-089c-4b19-8aa8-c31ac8419816' \
  --header 'If-Match: 3' \
  --header 'Content-Type: application/json' \
  --data '{"content":"Prefers concise answers"}'
```

</CodeGroup>

You may send `expected_revision` in the JSON body instead. A stale revision returns 409; read the current value before deciding whether to retry.

<Heading url="/apps/{app_key}/memory/settings" method="GET / PATCH" title="Read or update memory settings" name="#Memory-Settings" />

GET returns memory, automatic capture, writable slots, and configuration revision. PATCH updates `memory_enabled` or `auto_capture_enabled` with optional revision protection for the current External User ID and App relationship.

<Heading url="/apps/{app_key}/memory/operations/{operation_id}/undo" method="POST" title="Undo a memory operation" name="#Undo-Memory" />

The operation must belong to the current External User ID and App and remain inside its undo window. Repeated, expired, or foreign operations fail safely.

## Runtime Key rotation

1. Create a new Runtime Key in the console.
2. Deploy it to the calling backend.
3. Verify Apps, Chat, file, and memory calls.
4. Revoke the old Key.

Rotation does not change App IDs, Subjects, files, conversations, or memory ownership.

## Error handling

```json
{
  "code": "401001",
  "message": "Please login first"
}
```

| HTTP status | Recommended action |
| --- | --- |
| 400 | Validate parameters and request body |
| 401 | Check whether the Runtime Key is missing, expired, or revoked |
| 403 | Check Runtime Workspace and App status |
| 404 | The resource does not exist or is owned by another External User ID |
| 409 | Refresh the revision or inspect the idempotent operation |
| 413 | Reduce file size |
| 429 | Retry according to `Retry-After` |
| 500 | Retry safe mutations with the same idempotency key and retain the request ID |

Responses include `X-Request-ID`. Share that value with operators without sharing the Runtime Key.

## Isolation scopes

| Resource | Scope |
| --- | --- |
| Runtime Key | Runtime Workspace |
| App | Runtime Workspace + App ID |
| External Subject | Runtime Workspace + External User ID |
| File | Runtime Workspace + External Subject |
| Conversation | Runtime Workspace + External Subject + Agent |
| Memory | Runtime Workspace + External Subject + Agent |
