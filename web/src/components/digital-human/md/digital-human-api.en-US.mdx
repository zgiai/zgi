# DigitalHuman API

Use this API to invoke the latest published version of a DigitalHuman from an external system. The API is streaming-only and authenticates with a key bound to that DigitalHuman.

<div>
  ### Base URL

<CodeGroup title="Code">

```text
{apibase}
```

</CodeGroup>

### Authentication and user identity

Send the DigitalHuman API key from your server with `Authorization: Bearer`. Every stateful request must also include a stable, non-identifying, case-sensitive `user` value.

- The API key identifies the integration; `user` identifies the data owner.
- One key can serve many users, while conversations, files, and relationship memory remain isolated by `user`.
- Rotating a key does not change data ownership for the same `user`.
- Never expose the API key in browser code.

    ### Main events

    - `run_accepted`: the durable run was accepted and includes `run_id`.
    - `message_start`: the message exists and includes `conversation_id` and `message_id`.
    - `message` / `message_delta`: response content chunks.
    - `message_end`: the terminal message state.
    - `error`: a safe public error.
    - `run_end`: the single terminal event for the run.

    The `X-ZGI-Run-ID` response header matches `run_accepted.run_id`. Save event IDs so an interrupted stream can be resumed through Run Events.

## Conversation, run, and file endpoints

- `GET /digital-humans/config`: read the published public configuration.
- `GET /digital-humans/runs/{run_id}`: inspect run status.
- `POST /digital-humans/runs/{run_id}/stop`: stop a run.
- `POST /digital-humans/runs/{run_id}/runtime-input`: submit runtime input.
- `GET /digital-humans/conversations`: list conversations.
- `GET /digital-humans/conversations/search`: search conversations.
- `GET/PATCH/DELETE /digital-humans/conversations/{id}`: manage one conversation.
- `GET /digital-humans/conversations/{id}/messages`: read message history.
- `POST /digital-humans/files/upload`: upload a file owned by the current `user`.

GET and DELETE requests receive `user` in the query string. POST, PATCH, and multipart requests receive it in the body or form field.

## Errors and retries

- `400`: invalid request shape or `user`.
- `401`: missing, invalid, expired, or revoked key.
- `403`: DigitalHuman API access is disabled.
- `404`: the resource does not exist or belongs to another `user`.
- `409`: the idempotency payload changed or the run state conflicts.

Use bounded exponential backoff only for retryable errors. Reuse the original `request_id` when retrying the same logical request.
