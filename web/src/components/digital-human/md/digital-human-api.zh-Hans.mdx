# 数字人 API

使用该接口从外部系统调用当前数字人的最新发布版本。接口只支持流式响应，并使用绑定到该数字人的 API Key 鉴权。

<div>
  ### Base URL

<CodeGroup title="代码">

```text
{apibase}
```

</CodeGroup>

### 鉴权与用户身份

请在服务端通过 `Authorization: Bearer` 发送数字人 API Key。每个有状态请求还必须传入稳定、不含个人信息且大小写敏感的 `user`。

- API Key 标识调用方，`user` 标识数据主体。
- 一个 Key 可以服务多个 `user`，不同 `user` 的会话、文件和关系记忆相互隔离。
- 轮换 Key 不会改变同一 `user` 的数据归属。
- 不要在浏览器代码中暴露 API Key。

## 会话、运行和文件接口

- `GET /digital-humans/config`：读取已发布配置与能力。
- `GET /digital-humans/runs/{run_id}`：查询运行状态。
- `POST /digital-humans/runs/{run_id}/stop`：停止运行。
- `POST /digital-humans/runs/{run_id}/runtime-input`：提交运行时输入。
- `GET /digital-humans/conversations`：分页读取会话。
- `GET /digital-humans/conversations/search`：搜索会话。
- `GET/PATCH/DELETE /digital-humans/conversations/{id}`：管理单个会话。
- `GET /digital-humans/conversations/{id}/messages`：读取消息历史。
- `POST /digital-humans/files/upload`：上传当前 `user` 专属文件。

GET 和 DELETE 请求通过 Query 传入 `user`；POST、PATCH 和 multipart 请求通过正文或表单字段传入 `user`。

## 错误与重试

- `400`：请求格式或 `user` 非法。
- `401`：Key 缺失、无效、过期或已撤销。
- `403`：数字人 API 入口已关闭。
- `404`：资源不存在，或不属于当前 `user`。
- `409`：幂等 ID 对应的请求载荷发生变化，或运行状态冲突。

只对可重试错误使用有上限的指数退避。相同逻辑请求重试时必须复用原 `request_id`。
