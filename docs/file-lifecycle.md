# File retention

User uploads and files generated by chat or Agent tools are retained by default. This includes uploads marked `is_temporary`: that flag limits where the file can be used and displayed, but does not set a retention deadline. Deleting a file explicitly remains possible.

AIChat attachment uploads that carry an upload-attempt id are a scoped exception: an attempt
that is cancelled or never claimed by a sent message expires after 24 hours (a cancellation
tombstone is retained for one hour to close an upload race). This cleanup applies only to
those abandoned draft attempts; it does not restore the old global `is_temporary` expiry task
and does not affect ordinary temporary files.

The generated-file response may still use the legacy `target: temporary_artifact` label to distinguish an unsaved artifact from a File Management asset. The authoritative retention fields are `lifecycle` and `expires_at`.

An explicit temporary output lifecycle on a workflow (for example, an image generation node configured with `lifecycle: temporary`) is the exception. Those output files expire according to the workflow's configured deadline, or after seven days when no deadline is given, and the scheduled workflow-file cleanup removes expired content.

Download links may have a short validity period independent of file retention. Refresh the conversation or request a new signed URL to access a retained file after its link expires.

The migration on deployment clears expiry from existing conversation-bound generated files. It cannot recover files whose stored content was already deleted. Files without a conversation binding are not migrated because they may be explicitly temporary workflow outputs.
