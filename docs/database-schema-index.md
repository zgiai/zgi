# AI 表结构索引

AI 表结构索引帮助自动选表找到与问题相关的数据表。它保存表结构的向量和全文信息，不修改业务数据，也不是加速 SQL 执行的数据库索引。

## 使用

在数据库侧栏点击 **AI 表结构索引**，索引页面会在数据库主内容区域打开。确认默认向量模型后点击 **建立索引**。这同时启用后续自动更新，模型调用费用归属数据库所在工作空间，表结构信息会发送给配置的向量模型服务。

- 查看进度需要表结构查看或管理权限；建立和重试需要表结构管理权限。
- 离开页面不会停止后台构建。
- 已完成的表保留结果，失败表可重试。界面只展示安全的错误分类，详细原因记录在服务端日志中。
- 页面下方按时间倒序展示持久化更新记录，每页 20 条。同一轮表任务汇总为一条，展开后可查看涉及的全部表及失败表的安全错误分类。记录首次建立、表结构变化、默认向量模型变化和手动重试；上线前已有的历史索引不会补造记录。
- 后台每分钟启动一轮检查；实际检测延迟还取决于表数量和依赖服务响应时间。新增、删除、字段或注释变化会更新对应索引；默认向量模型变化会准备新版本。
- 数据库移动到其他工作空间后，旧任务不再发布有效结果，并清理旧索引。需要在目标空间重新点击建立，确认费用归属。

工作流自动选表不再同步建立索引。所有当前表结构的索引就绪后才能使用，缺失或过期时明确失败，不以部分表代替整个数据库。符合当前工作空间、模型和结构版本的历史索引可以复用，但不会因此自动启用后续付费更新。手动选表不受影响。

第一版不提供暂停、取消或手动删除索引。

## 部署与运行

先部署数据库迁移，再启动新版 API。新增迁移为 `20260831090000_create_database_schema_index_settings`，保留原有 `text2sql_schema_indexes` 数据。

```sh
cd api
go run ./cmd/migrate up
```

后台复用 PostgreSQL、现有 Redis 任务队列的 `low` 队列及配置的向量数据库，无需独立服务。每张表的构建期限为两分钟，自动尝试最多三次，之后由用户重试。权限、工作空间、表或模型失效时停止该任务的自动尝试。

PostgreSQL 保存用户开启记录、目标索引及尝试次数。定期检查会重新提交漏发的任务，包括 Redis 暂时不可用、进程退出等情况。表级数据库锁避免多个实例同时构建或清理同一张表；进程退出后锁由数据库释放。索引任务执行前后均校验范围和版本。

任务允许重试，不承诺外部模型调用恰好一次：若进程在模型调用完成、保存成功状态之前退出，恢复时可能再次调用模型。已保存为就绪的当前索引不会因重复任务而重新调用模型。

接口位于现有数据库认证范围下：

- `GET /data-dbs/:id/schema-index`：查看进度和安全错误分类。
- `GET /data-dbs/:id/schema-index/runs`：分页查看当前工作空间内的更新记录。
- `POST /data-dbs/:id/schema-index`：开启并提交构建意图，或重试未完成索引。

## 验证

```sh
cd api
go test ./internal/capabilities/text2sql ./internal/modules/datasource/handler ./internal/modules/app/workflow/nodes/sqlgenerator
```

将 `ZGI_SCHEMA_INDEX_TEST_DSN` 设置为独立的 PostgreSQL 测试库连接串（键值格式），可执行真实数据库集成测试。测试创建并清理临时 schema；迁移测试在事务中运行并回滚，请勿指向业务数据库。

```sh
go test ./internal/modules/datasource/indexing ./internal/migrations -run 'TestPostgres|TestDatabaseSchemaIndexMigrationPostgres' -count=1
```

集成测试使用模拟向量模型和内存 Redis，不产生模型费用。覆盖 200 张表分批完成与恢复、并发重复投递、超时重试上限、权限限制和模型/工作空间变化。真实模型延迟、队列服务重启及实际环境负载仍应在部署验证中检查。
