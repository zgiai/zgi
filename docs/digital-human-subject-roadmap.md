# 数字人主体化与终端用户隔离：后续路线

本文跟踪两个设计目标的落地进度，以及剩余工作的拆分顺序。设计依据见
`docs/architecture/decisions/` 下的 ADR 0001、0002、0004、0005、0006、0007。

## 两个目标

1. **数字人是一个主体。** 旧设计把任务按用户或会话切成互不可见的命名空间，
   数字人看不到自己的完整工作量，偏离了 ADR 0001。
2. **对外服务多用户时，最终用户要隔离，也要方便管理。** 数据隔离已经具备，
   但运营方无法列出、管理、导出或删除某个最终用户。

2. 补齐验收矩阵（已在本地完成，渠道入口除外），覆盖每个入口和可信度：
   - 非管理者成员：看到他人的工作区任务为只读，任务工具拒绝修改只读任务；

## 阶段二：补齐主体化的管理入口

1. 任务中心为管理者提供可见性切换（`requester`、`workspace`、`restricted`），
   改动写入任务活动记录。
2. 记忆管理支持把已有 `self` 记忆重新划分到业务范围，或归档。
3. “我的任务”卡片显示“有修改待确认”，点击跳转到对应会话的审批卡。
   需要任务列表接口返回待审批标记。

验收：管理者无需改库即可调整任务可见性和记忆范围。

## 阶段三：终端用户实例（ADR 0006）

目标：对外部署时，每个最终用户拥有独立的连续性，运营方可以按用户管理。

1. **实例记录。** 新增 `digital_human_end_user_instances`，运行准入时按
   （数字人，用户主体）幂等创建，并固定在运行上。
2. **实例记忆。** 新增 `instance` 业务范围：外部用户只能写入自己的实例范围，
   召回时读取 `self` 和本实例范围；实例记忆不会自动流入 `self`，
   只能由有权限的成员审阅后提升。
3. **关联数据。** 会话、文件、运行、任务增加可空的 `instance_id`；
   一次性任务按用户主体关联历史数据。
4. **WebApp。** 宿主签名的用户令牌对应持久实例；匿名会话对应临时实例，
   不写实例记忆，随会话过期。
5. **控制台管理。** 数字人下新增“终端用户”页面：列表、用量、暂停与恢复、
   导出、删除（保留只含标识和时间的墓碑记录）、单实例配额。
6. **对外管理接口。** `GET /end-users/{user}`、
   `POST /end-users/{user}/export`、`DELETE /end-users/{user}`。
7. **审计。** 实例创建、暂停、导出、删除、配额变更、实例记忆提升均记审计事件。

8. **按用户的连接器凭据（ADR 0007）。** 连接器绑定增加 `credential_mode`：
   `shared`（现状，使用配置人委派的连接，以数字人身份行动）和
   `per_user`（使用请求人自己的连接，以请求人身份行动）。顺序：
   - 先支持控制台成员：成员已有个人连接，为数字人的每个槽位选定一次；
   - 实例上线后支持外部用户：连接归实例所有，通过
     `POST /end-users/{user}/connections` 或 WebApp 托管连接页提交 Key；
   - 缺少连接时提示“需要连接”，不回退到共享凭据；
   - 运营方可查看连接健康状态、强制断开，删除实例时级联删除凭据。

开关：`ZGI_DIGITAL_HUMAN_INSTANCES_ENABLED`（管理面）、
`ZGI_DIGITAL_HUMAN_INSTANCE_MEMORY_ENABLED`（实例记忆）、
`ZGI_DIGITAL_HUMAN_PER_USER_CONNECTORS_ENABLED`（按用户连接器），默认关闭。

验收：

- 同一数字人对两个外部用户各自记住不同的约定，互不可见；
- 删除一个用户后，其会话、文件、实例记忆、关系记忆、任务全部清除，
  其他用户不受影响；
- 暂停的实例拒绝新运行，其定时任务暂停；
- 并发首次请求只创建一个实例；
- 两个外部用户各自绑定自己的邮箱，数字人只能以当前用户的账号操作，
  读到的数据只进入该用户的实例记忆；
- 用户未连接时数字人提示连接，不会改用共享凭据。

## 阶段四：业务范围与周边能力

1. 引入项目、客户、营销活动实体，由资源绑定解析可读写范围。
2. 任务的业务范围（ADR 0005 留待后续决策）。
3. 审批中心：按任务标识关联审批请求，复用 `requester`、`origin`、`confirmed_by`。
4. 成果库：任务结果和记忆按标识引用成果，不复制内容。

## 待决问题

- 实例记忆是否需要容量上限和过期策略。
- 同一最终用户跨多个数字人是否需要统一身份。当前设计中，同一 `user`
  在不同数字人下是不同主体。
- 渠道私聊是否映射为渠道成员的实例。
- 配额按实例计费还是仅限流。
- `per_user` 槽位能否显式配置“未连接时使用共享凭据”，以及如何向用户明示。
- 同一最终用户能否在多个数字人之间复用同一个连接。
- OAuth 类连接器何时支持（当前只支持 Key 类）。
